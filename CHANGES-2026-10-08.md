## 1. Higgsfield models

### Before

Only **Ideogram 4** (photos) and **Wan 2.7** (image to video) really worked. Soul, Kling and
Seedance were placeholders with no endpoint. Requests sent fields that Soul doesn't accept, and
every result was saved as a PNG, including videos.

### Now (`studio-agent`)

One Higgsfield key unlocks this catalog:

| Type | Model | What it's for | What it accepts |
| --- | --- | --- | --- |
| Photo | **Soul 2** | Photoreal fashion and editorial images | 7 aspect ratios, 720p/1080p, seed |
| Photo | **Soul** | The original Soul; 1 reference image steers the look | Same as Soul 2, plus 1 reference |
| Photo | **Soul Cinema** | Cinematic stills: film lighting and grade | Same as Soul 2 |
| Photo | **Grok Image 2** | From text, or edits up to 10 reference images | 7 aspect ratios, 1k/2k |
| Photo | **Ideogram 4.0** | Photos and graphics; remix a product photo | Aspect ratio, speed, image weight |
| Video | **Kling 3.0 Pro** | Strong motion, native sound | 16:9, 9:16, 1:1 · 5/8/10/15 s · start and end frame |
| Video | **Seedance 2.0** | Cinematic shots with generated audio | 6 aspect ratios · 5–15 s · 480p to 4K · start and end frame |
| Video | **Hailuo 2.3** | Fast, cheap 768p drafts | 6 or 10 s · text or start frame |
| Video | **Wan 2.7** | Brings a still image to life | Needs an image · 720p/1080p |

**How it works**

- Each model is one entry in `backend/config/ai.php`, copied from its request schema on
  docs.higgsfield.ai: its endpoint (and image-to-video endpoint), accepted aspects, lengths,
  resolutions, where input images go, and how sound is switched on.
- The Studio and Creative Lab only show the options the chosen model accepts.
- `HiggsfieldProvider` changes any other value to the nearest accepted one, so a request never
  fails because of a field the model doesn't know.
- Results are typed from their real content (video or image), not always PNG.
- Adding a new Higgsfield model only needs a new entry in `config/ai.php`, no code.
- Campaign agents now use **Soul 2** for images and **Kling 3.0 Pro** for video.

**Set up**

1. In `backend/.env`, set `HIGGSFIELD_KEY_ID` and `HIGGSFIELD_KEY_SECRET` (from console.higgsfield.ai).
   Keep the key there only, never in `.env.example` or a commit.
2. `docker compose restart api worker`
3. Open the **Models** page and press **Test**. The test is free.
4. Optional: `HIGGSFIELD_PLAN=soul-2,kling-3-pro` limits the list to what your plan includes.

### ComfyUI (your own GPU)

- Set `COMFYUI_URL` in `backend/.env`. From inside Docker, a ComfyUI on this PC is
  `http://host.docker.internal:8188`. ComfyUI must be started with `--listen`.
- Workflows are exported with *Save (API Format)* into `backend/resources/comfyui/`.
  **Z-Image Turbo** is ready to use.

### Creative Lab and Gallery

Both are in the sidebar under **Create**.

- **Creative Lab** (`/dashboard/lab`): made for Reels and TikTok. Pick the destination (Reels,
  TikTok, Shorts, Story, feed), a hook template and a look, then make 1–4 takes. The preview shows
  the result on a phone with the app's buttons, caption and safe zone on top.
- **Gallery** (`/dashboard/gallery`): every finished photo and video. **Remake** opens the Lab with
  the same prompt, model and settings. **Animate** turns a still into the first frame of a video.

### Generation fix

A generation could stay on "Queued" forever. The API, the worker and the phone agent all write to
the same SQLite file; when two wrote at once, the job failed and nothing marked it as failed.

- SQLite now waits for its turn instead of failing (`backend/config/database.php`).
- If a job dies, the card shows **failed** with a **Retry** button (`RunGeneration.php`, `PollGeneration.php`).
- Soul 2 normally takes 10–40 seconds. If a card stays on "Queued" for more than about 30 seconds, something is wrong.

### The other version (`campaign-studio-flow` branch)

This branch built its own Higgsfield catalog the same day. It covers the same models, with these differences:

- Different model IDs: `soul-v2` here, `soul-2` on `studio-agent`. The limits sit in a
  `capabilities` block instead of separate fields.
- **Google models** added: Gemini 3.1 Flash Image, Veo 3.1 Fast and Veo 3.1 (needs `GEMINI_API_KEY`).
- Text AI uses `gateway/glm-5.3-flash` through an OpenAI-compatible gateway such as Ollama Cloud
  (`AI_GATEWAY_URL`, `AI_GATEWAY_KEY`) instead of Claude.

When merging, keep **one** catalog and one set of model IDs.

## 2. Campaign studio

Branch `campaign-studio-flow`. The main commit is `c67bc6d`, *"Make the campaign studio reachable,
from the brief to the calendar"*.

### What was wrong

The campaign step screens existed but weren't connected. After the interview, the brief was left
there with nothing to click.

### Now: five steps on the Campaigns page

1. **Brief**: an AI interview asks one question at a time and fills a 25-field client brief.
2. **Plan**: approval gate **6A**.
3. **Production**: shows content being made. It keeps checking while anything is generating, so a
   long video doesn't look stuck.
4. **Review**: approval gate **6B**. Videos play inline. Each post can be approved, edited, sent
   back to be rewritten, or deleted.
5. **Schedule**: suggests times from your queue slots, shows them before booking anything, then
   hands over to the calendar.

- The page moves to the next step on its own when the current one finishes. If you go back to
  re-read an earlier step, it stays there.
- **You don't need social accounts to plan any more.** The writer works from the brief alone. A post
  with no account of its own goes to all accounts.
- New **Inspirations** feature: a database table, API endpoints and a screen under Media.

## 3. Connecting the phone

### How it fits together

```
FlowAI dashboard (browser)
        │
FlowAI API (Laravel, Docker, :8000)
        ▲   /api/agent/*  with the agent token
        │
FlowAI agent (Python, agent/ folder, on the PC the phone is plugged into)
        │   adb (USB or Wi-Fi), scrcpy for the live view
        ▼
Android phone with Instagram / X signed in
```

The agent asks FlowAI for jobs. FlowAI never connects to the phone directly. This means the
website can be hosted online later, while the agent still runs on the PC next to the phones.

### Set up the phone (once)

1. On the phone: **Settings → About phone → tap Build number 7 times**.
2. **Settings → Developer options → USB debugging** on.
3. Plug it in with USB and accept **Allow USB debugging** (tick "Always allow").
4. Sign in to Instagram (and/or X) **on the phone, by hand**. The agent never types passwords.

### Set up the agent (once)

```powershell
cd C:\Users\SBE\content-generator\agent
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
copy .env.example .env
```

In `agent\.env`, set `FLOWAI_AGENT_TOKEN`. The token is on **Dashboard → Phones → The automation
service** (Show → Copy). `adb` is found on its own in `C:\platform-tools`.

Check and prepare the phone:

```powershell
.venv\Scripts\python -m flowai_agent phones            # lists phones and what they still need
.venv\Scripts\python -m flowai_agent prepare SERIAL    # turns animations off, sets Gboard as keyboard
```

### Run it

```powershell
.venv\Scripts\python -m flowai_agent
```

1. Within 30 seconds, the phone appears on the **Phones** page, online, named after its model.
2. In FlowAI: **Accounts** → the Instagram/X account → link it to that phone → turn **automation** on.
3. Approved, scheduled posts on that account now publish from the phone by themselves. Each run,
   with its steps and screenshots, is on the **Publishing** page.

Keep the agent running while you want phones to post.

### Wireless instead of USB (Android 11+)

On the phone: Developer options → **Wireless debugging** → *Pair device with pairing code*. Then:

```powershell
.venv\Scripts\python -m flowai_agent connect 192.168.1.42:41235 123456 37099
#                                             connect address    code   pairing port
```

### Scan for devices (new)

**Phones → Scan for devices** lists everything this PC can drive:

- **Connected:** USB phones, Wi-Fi phones and running emulators, each one ready, waiting for
  *Allow USB debugging*, or offline. Ready devices join FlowAI by themselves.
- **On this Wi-Fi:** phones with Wireless debugging on. Connect with one tap, or pair with the 6-digit code.
- **Android emulators:** emulators from Android Studio, started with one tap. None are installed on this PC yet.
- **Simulators:** add FlowAI's built-in simulator, or switch the agent's virtual phone on or off.

The same list in a terminal: `.venv\Scripts\python -m flowai_agent scan`.

### Live view (new)

On the Phones page, **Live** shows the phone's screen. You can tap, drag, use Back / Home / Apps,
and type. It is served by the agent at `http://localhost:8765` and needs the agent token.

- With **scrcpy** installed (`winget install Genymobile.scrcpy`), the view is smooth (up to 24 fps).
  Without it, it falls back to about 2 screenshots per second.
- While a post is publishing you can watch, but taps are blocked until the run ends.

### How a run ends

- **confirmed**: the profile's post count went up **and** the newest post has the caption. Screenshots are kept as proof.
- **failed**: a step didn't work, for example a button wasn't found. The screenshots show where it stopped. FlowAI retries it later.
- **uncertain**: Share was tapped but the post couldn't be proved. It is **never** retried
  automatically, so the account doesn't post twice. Check the account, then use **Confirm live** or
  **Try again** in the Inbox.

Limits were raised for real phones: up to **60 steps** (was 40) and **420 seconds** (was 240) per
run, because a real Instagram post takes 35–50 actions and a video can take minutes to upload
(`PUBLISHING_STEP_BUDGET`, `PUBLISHING_HARD_TIMEOUT`).

### Tested on a real phone

**Pixel 7a, Android 16, Instagram:** a real post went out end to end and ended **confirmed** (post
count 3 → 4, caption found). Fixes made during the test:

- After Share, Instagram returned to the previous app, so the agent couldn't check the profile. The
  agent now reopens Instagram before checking. The same fix applies to X.
- The live view froze with scrcpy 4.1 (a renamed option and a frame problem with ffmpeg 7.1). The
  first frame now arrives in under a second.
- The test suite was deleting real media files from local storage. All tests now use a fake disk.

### Known limits

- **Carousels** (several photos in one post) aren't supported yet. Such a run fails with a clear note.
- **Emoji and accented letters** can't be typed through adb; they're dropped from captions.
- A different Instagram/X version may name a button differently. The run then fails at that step, and
  the button is fixed in `agent/flowai_agent/devices/targets.py`, or in `agent/data/targets.json` for one phone.
